# 图表管理

此处保存论文图与登记记录。`v2_reference/` 已复制三张现有 v2 交付图，源自 `../../A题_代码包/deliverables/figs/`；它们目前仅供写作参考，未独立复核，也未引用到正文。登记表区分候选图与已有参考图。

## 命名与交付

使用英文小写、下划线和版本号，例如 `fig_q1_makespan_v01.pdf`。每张实验图配套保存：

- 成图：本目录中的 PDF（优先用于线图等矢量图）及 PNG 预览。
- 数据：`../data/processed/` 中同名的 CSV/JSON/NPZ 等可复用数据。
- 脚本：`../scripts/` 中生成该图的代码，注明运行环境与命令。
- 记录：`figure_registry.csv` 中的数据来源、版本、单位、图题、正文标签和核验状态。

数据格式和绘图后端按实际任务选择；没有原始结果时不生成假数据曲线。示意图应明确标注为示意，不伪装成实验结果。

## 成图检查

1. 单位、图例、颜色含义、基线与正文一致；条形图坐标原点和截断处理不能误导。
2. 图内不重复放论文图题，图题写在 `论文.tex` 的 `caption` 中。
3. 按最终版面检查文字大小、中文字体和可辨识性，优先使用矢量输出。
4. 确认核验完成后，再在正文启用 `includegraphics`；不使用不存在的图片路径。
5. 更新图时同时更新数据、脚本、登记表及论文引用；保留不同版本以便追溯。

团队目录规范建议 300 dpi，并要求额外保存绘图数据。当前 v2 参考图的绘图数据 NPZ 未在源图目录中找到，需补齐后再作为完整可重绘工件交付。

登记表状态建议：计划 → 数据齐备 → 已出图 → 已核验 → 已入文。无数据时保持“计划”。
