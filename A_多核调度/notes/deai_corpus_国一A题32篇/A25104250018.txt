题
目:
多层协同优化的神经网络处理器核内调度算法研究
摘
要：
基于单指令多数据流架构的NPU 因硬件设计简单、面效高等优势而备受推理任务的
青睐。本文研究通用神经网络处理器下的核内调度问题。针对华为Davinci 架构硬件平台
在复杂计算图调度中面临的峰值内存控制、缓存资源管理和执行时间优化等多重挑战，建
立多目标融合的自适应列表调度模型、硬件仿真框架模型、多层次协同内存管理模型和两
阶段时间优化模型，实现从基础调度到性能优化的完整技术链条。
针对问题一，建立基于多目标融合的自适应列表调度算法，设计四层协同架构实现峰
值内存驻留最小化。构建预测性缓冲区特征分析层，通过生存期效率分析、内存压力评估
和关键路径权重计算实现精确特征提取；建立多目标动态优先级决策层，融合内存效率、
执行效率和资源利用率实现智能调度决策；设计内存压力自适应调度层，通过压力感知
和峰值邻域检测实现动态策略调整；构建分层协同全局搜索优化层，结合三阶段局部重排
和二分搜索框架实现系统性优化。算法对于节点的时间复杂度为O(|N|2)，在六个示例上
的优化效果为：Matmul_Case0 峰值内存降至7,178 字节，Matmul_Case1 为21,504 字节，
FlashAttention_Case0 为23,552 字节，FlashAttention_Case1 为66,048 字节，Conv_Case0
为29,216 字节，Conv_Case1 为105,380 字节，相比传统贪心算法峰值内存平均降低91.2%，
最大优化幅度达94%。本文提出的自适应列表调度算法在上述样例中的执行时间分别为
0.10s、9.69s、0.04s、0.47s、0.07s、16.66s，验证了算法的高效性和可扩展性。
针对问题二，构建Davinci AiCore 硬件仿真框架并设计多层次协同的自适应内存管理
算法，实现带约束的动态内存分配与缓存优化。首先建立层次化缓存抽象模型，定义连续
性约束、非重叠约束和L0 缓存独占约束的完整约束体系。在此基础上设计智能地址分配子
系统，采用多策略融合分配器和碎片化感知策略，通过剩余生命周期、下次使用距离、碎片
化贡献、未来分配压力和使用频率五个维度综合评估SPILL 优先级。最后构建协同优化子
系统，集成局部重调度机制和COPY_IN 替代策略。在六个测试用例中应用上述优化，结果
表明，算法总运行时间为43.789 秒，成功管理9,874 个缓冲区，完成2,064 次SPILL 操作，
总额外数据搬运量为306,206 字节。各用例具体数据搬运量分别为：FlashAttention_Case0:
1
9,020 字节、Conv_Case0: 68,314 字节、Matmul_Case0: 10,240 字节、FlashAttention_Case1:
50,544 字节、Matmul_Case1: 57,344 字节、Conv_Case1: 110,744 字节。缓存碎片化控制效
果显著，L1 缓存平均碎片化率为18.7%，UB 缓存平均碎片化率仅为8.4%。考虑到模型的
通用性，我们采用最优页面置换算法给出条件理论最优解分析，确保优化结果的合理性。
针对问题三，提出两阶段时间优化策略，实现执行时间与数据搬运量的多目标联合优
化。第一阶段基于关键路径列表调度算法，通过关键路径余时计算和事件驱动调度策略优
化节点执行顺序；第二阶段应用生命周期压缩、SPILL 预取和局部搜索技术，通过空洞填
补和相邻节点交换实现精细调优。建立多目标权衡评估机制，为不同应用场景提供灵活的
优化方案选择。在整体性能方面，相对于问题二基准，两阶段优化策略显著提升了时间性
能。总执行时间从基准的4,940,058 周期分别减少至3,120,792 周期和2,973,690 周期，实
现36.8% 和39.8% 的优化幅度。与此同时，为获得时间性能提升，数据搬运量有所增加，
总额外数据搬运量从306,206 字节上升至368,158 字节，且在二阶段优化上升至1,085,957
字节，增幅分别为20.2% 和254.6%，可根据性能与精度权衡选择优化方案。在测试用例
中，Matmul 类算子优化效果最为显著：Case0 执行时间降低66.7% 至99,488 周期，Case1
降低62.6% 至966,059 周期。FlashAttention Case0 通过第二阶段优化实现32.6% 的性能提
升，最终达到49,988 周期。Conv Case0 也获得6.3% 的改进，优化至452,035 周期。在多目
标权衡方面，算法的时钟周期平均降低31.9%，且一阶段优化无明显搬运数据量激增，在
时间优化与空间开销之间达到平衡，成功实现了多目标联合优化。
解决上述问题后，根据约束条件对结果进行严格校验，并给出优缺点分析与模型推广。

1 问题综述
1.1 问题背景
近年来，人工智能技术的不断突破，推动着深度神经网络在语音识别、图像处理、自
然语言处理等领域的广泛应用。随着深度学习推理模型的规模和计算量持续增长，传统
GPU 和CPU 出现了高功耗和高延迟问题，阻碍了神经网络在边缘设备的落地应用。因此，
为满足高效推理的需求，业界开发了各类神经网络的专用加速芯片，通用神经网络处理器
（Neural Processing Unit，NPU）便是其中的代表
[1]。一类NPU 凭借其设计简单的单指令多
数据流（Single Instruction Multiple Data，SIMD）架构，能够在功耗和空间受限的边缘端高
效地执行推理任务，展现出卓越的并行计算能力。然而，SIMD 型NPU 的核内适配与调度
复杂，需要在细粒度计算图上决定执行顺序与缓存分配，并在多执行单元与多级缓存约束
下优化调度策略。由于手工编排模板的泛化能力较弱，需要设计一种面向细粒度计算图的
通用自动调度算法，促进SIMD 架构NPU 的规模化应用。

通用的自动调度算法成为亟待解决的问题。

1.2 数据分析
本赛题提供的示例输入数据采用统一的图结构格式，分为JSON 和CSV 两种文件格式，
描述六种任务的计算示例图模型(如Matmul_Case0/1、FlashAttention_Case0/1、Conv_Case0/1)。
这两种格式在数据内容上完全一致，差别仅在于结构组织和存储形式。根据实际建模过程
中对数据解析和属性调用的需求，可以灵活选择使用JSON 或CSV 格式，为后续的图结构
分析、节点调度优化等工作提供统一的数据基础。
1.2.1 JSON 格式
在JSON 表示中，每个任务示例对应一个独立的文件，例如：任务名.json。该文件通
过“顶级字段-子结构”的层级设计直接映射图模型的核心逻辑，包含仅有的两个顶级字
段：Nodes 和Edges。
(1) Nodes 列表：包含图中的所有节点，包括计算操作节点（如CONV、MOVE、COPY_IN
等）和缓存管理节点（如ALLOC、FREE 等）。每个节点以一个字典（JSON 对象）描
述，并根据节点类型动态包含不同键值属性：
• 对于操作节点：包含Pipe（执行管道，例如MTE1、CUBE）、Cycles（执行周期）、
Bufs（依赖的缓存列表）等属性，用于描述该操作的执行单元、耗费的周期和所依
赖的缓存。
8
• 对于缓存管理节点：包含BufId（缓存标识符）、Size（缓存大小）、Type（缓存级
别，如L1、L0B 等）等属性，用于标识和描述缓存空间的分配与释放情况。
(2) Edges 列表：定义节点间的有向依赖关系。每条依赖边以数组形式表示，例如[9,
10] 表示源节点9 的输出作为目标节点10 的输入。通过此类二元数组即可清晰体现依
赖方向，无需额外字段即可直接表征图中的有向边关系。
1.2.2 CSV 格式
以CSV 表示时，节点信息和边信息被拆分存储在两个文件中：一个节点信息文件和
一个边信息文件。
(1) 节点信息文件：以表格形式呈现节点属性。首行是字段标题，涵盖所有可能的节点
属性列，例如：Id、Op、BufId、Size、Type、Pipe、Cycles、Bufs 等。不同类型的节点
在对应行填入相关属性值，未涉及的字段则留空。例如：
• ALLOC 节点：需要填写BufId、Size、Type 等字段（表示分配的缓存标识、大小
和级别），而像Pipe、Cycles 等执行相关字段对ALLOC 来说无意义则留空。
• COPY_IN 节点：需要填写Pipe、Cycles、Bufs 等字段（表示使用的执行单元、执
行周期、依赖缓存），而与缓存分配无关的字段如Size、Type 则空置。
通过这种方式，不同节点类型的数据在CSV 中得到统一但灵活的表示，列字段与JSON
的属性一一对应。
(2) 边信息文件：专注于图的依赖关系，仅包含两列：StartNodeId（起始节点ID）和
EndNodeId（目标节点ID）。每一行表示图中的一条有向边，直接对应JSON 格式
中Edges 列表里的一个二元数组元素。这样的设计确保了CSV 中的依赖关系表达与
JSON 保持完整一致，每条边都明确标识了源和目标，构成图的有向依赖结构。

1.4 名词解释
·算子（如矩阵乘Matmul、卷积Conv、注意力Attention 等）: 算子作为一种计算操
作手段，本质上是函数空间的相互映射，并且可以推广到任何空间，在深度学习领域的相
关计算中，算子表示对输入数据执行特定数学运算，产生输出的过程。
·SIMD 架构硬件平台（华为Davinci 架构平台）：单指令流多数据流架构采用一个控
制器，同时管理多个处理器，操作着一组数据，能够实现空间并行性的一种框架，适合图
像处理、科学计算以及深度学习等高度规则的数据并行任务。本文特指的华为Davinci 架
10
构平台，是华为公司为昇腾AI 处理器所设计的特定域架构，能够专注于神经网络推理训
练等AI 工作负载任务，其核心架构是异构计算单元和分层存储设计。
·硬件单元操作：硬件单元操作是硬件功能中的基础构建块，拥有确切的输入、输出
和时序特征，在数字电路中借助特定功能单元在固定周期内执行基本计算和逻辑动作。
·细粒度计算图：细粒度计算图能够拆解计算任务，得到如单个乘法、加法、数据移
动等原子操作单元，基于依赖关系构建有向无环图，图中的节点表示基本操作，边表示数
据流向和依赖。
·高度异构性：计算机内部系统中集成着的多种架构特质、功能特定且指令集可能互
不兼容的计算单元，针对具体计算任务进行硬件级优化。
·调度算法：系统资源管家操作系统，在面临多个进程请求使用有限资源的情况时，
需要采取对应手段选择合适的进程占用资源，这个过程就称为调度。为达到不同的系统目
标，研究人员制定了不同的调度算法。
·多级缓存：为平衡中央处理器（CPU）的高处理速度和主内存（DRAM）的缓慢速
度，在两者之间设置包含多个拥有不同级别、容量和速度的静态随机存取存储器（SRAM）
的层次结构。现代CPU 的常用三级缓存结构，少量极快但昂贵的L1 缓存（Level 1 Cache）
用于存储CPU 立即需要的数据，大量较快且便宜的L2、L3 缓存（Level 2 Cache、Level 3
Cache）存储近期可能用到的数据，能够较好地平衡速度、容量和成本。
·数据搬运（开销）：计算机中的CPU、GPU 以及NPU 中的核心等计算单元，在执行
计算任务时，需要在计算机存储层次结构的不同层级之间移动输入、权重以及中间结果等
数据，转移数据的过程称为数据搬运。而在数据搬运过程中，消耗的时间和能量，便是数
据搬运开销。
·有向无环图（DAG）：图结构是由若干个代表不同元素或实体的节点，以及连接节
点的边组成。若每条边上标有箭头从一个节点指向另一个节点，表示节点间的依赖关系、
先后顺序或信息流方向，并且从任意节点出发沿着有向边依次遍历，回不到出发节点，这
种” 有方向、无回路” 的图称为有向无环图，任务调度、拓扑排序、数据依赖分析等场景中
有着广泛应用。
·两类节点：
特定硬件系统往往包含两类节点，一类是操作节点，部署于硬件计算单元（如CPU 的
算术逻辑单元、GPU 的流处理器、专用运算模块等）内部，执行具体的计算任务，包括数
学运算和逻辑任务；另一类是缓存管理节点，独立运行在存储控制单元中，区别于操作节
点，其负责缓存资源的动态分配、释放和调度。
1.5 拟解决的问题
为综合权衡计算图的依赖关系、指令有序执行、多单元并行性以及缓存容量和地址空
间约束等各方面要求，需建立数学模型设计一种自动调度算法解决以下问题：
11
问题一：最小缓存驻留调度
（1）给定一个计算图DAG，包含操作节点和缓存管理节点两类节点。图中每个节点附
带执行单元、执行周期、所依赖的缓存等属性，边表示节点间的先序约束。
（2）由于硬件多级缓存容量有限，需要在保证依赖关系的条件下，确定一个覆盖所有
节点的可行调度序列，尽可能减小调度过程中驻留缓存峰值。
（3）针对所有给定的示例计算图，输出每个图的节点调度顺序（schedule.txt），同时计
算出该调度下的最大缓存驻留量，为后续缓存分配提供基础。
问题二：缓存分配与换入换出
（1）基于问题一得到的调度序列，考虑硬件实际缓存容量，比如L1、UB、L0A、L0B、
L0C 等均为有限区间，结合硬件缓存资源大小给出约束。
（2）实际分配缓存地址时，可能会导致并发缓冲区需求超过硬件容量的情况，需要引
入换入换出操作（SPILL），将部分缓冲区临时写回DDR，后续需要时再加载。本问题的核
心是在缓存容量限制的情况下，如何完成所有缓冲区的分配，且尽量减少额外数据搬运量。
（3）针对每个计算图，给出缓存地址分配方案（memory.txt），并记录换入换出操作
（spill.txt）。基于不同分配策略计算出调度过程的总额外数据搬运量。
问题三：性能优化策略
（1）基于已有的调度顺序和缓存分配方案，考虑执行单元之间可以并发工作，需要在
不显著增加数据搬运开销的前提下，尽量缩短计算图的总运行时间。
（2）问题二所得到的方案侧重于减少数据搬运量，但整体运行时间可能偏长。本问题
要求在额外数据搬运量不显著增加的前提下，通过改进调度顺序或优化缓存分配方式，降
低总执行时间，从而提高调度方案的综合性能。
（3）针对各示例计算图，输出新的调度顺序、缓存分配与SPILL 操作结果，并计算两
类核心指标：总运行时间和总额外数据搬运量。通过与问题二的结果对比，展示性能提升
效果，并以文本附件形式提交（schedule.txt、memory.txt、spill.txt）。
2 问题分析
通用神经网络处理器下的核内调度问题，可以概况为在空间、时间受限下，从有向无环
图（DAG）中得到满足拓扑序的调度序列。该类问题属于资源受限项目调度问题（RCPSP）
的衍生类型，是典型的NP-hard 问题。本文基于华为Davinci 架构平台，需要在硬件架构约
束下求得初始的调度序列；再进一步考虑因缓存资源死锁而产生的spill 分配策略；最终，
将总运行时间纳入考量，以获得完整的调度算法。本研究总体路线如图3所示。
问题一分析: 对于问题一，已知为输入为计算图以及每个节点需要的缓存大小，需要
满足拓扑约束和内存一致性约束，最终输出一个节点调度序列S，且使得S 在执行过程中
使用的最大驻留缓存容量最小，并且给出对于节点总数的时间复杂度分析。考虑到调度算

3 模型假设与符号说明
3.1 模型假设
1. 数据传输假设：假设数据传输是无损的，没有错位的；且忽略因信号传播延迟、时
钟抖动等原因造成的物理延迟。本假设有助于本团队构建一个可控的仿真环境，将视角更
加专注于调度和内存管理策略本身。
2. 问题一的特定假设：在问题一中，不考虑实际硬件上L1 和UB 缓存的长度限制，且
认为ALLOC 和FREE 节点本身不消耗执行周期。这是因为问题一仅关注调度顺序，且不
涉及缓存分配策略和总运行时间。
3.DDR 假设：假设DDR 容量无限且访问延迟固定，即当缓存空间不足时，数据可以
无限制地SPILL 到DDR（核外内存），且SPILL 操作的延迟和带宽是固定且可预测的。本
假设旨在简化了SPILL 操作的建模。
4. 缓存分配的连续性要求：假设每个缓冲区在分配过程中必须获得连续的物理地址空
间。如果本假设不成立，就不会出现内存碎片化问题，分配策略会有所不同。
5. 执行单元的独立性与无竞争：除了明确的资源约束（如L0 缓存独占性、Pipe 的独
占使用），不同执行单元之间的操作是相对独立的，不考虑它们之间可能存在的微架构竞
争（如共享总线带宽、寄存器文件冲突等）。本假设旨在简化了并行执行的建模，使得可以
独立计算不同Pipe 上的任务时间。

4 问题一的建模与求解
问题一主要分析的是通用神经网络处理器的核内调度问题，核心的目标是要构建出合
理的核内调度算法，为后续调度的空间优化工作与世间优化工作提高有效的支撑。
4.1 基础分析
通用神经网络处理器的核内调度问题可以概括为在资源受限下的有向无环图（DAG）
调度问题，该类问题属于资源受限项目调度问题（RCPSP）的衍生类型。在该类型中，模型
的计算流程被转换为DAG 的形式，其中节点不仅代表了在不同硬件单元上运行的计算算
子，还包含了申请和释放中间数据缓冲区的内存管理操作。调度任务目的是在满足拓扑依
赖关系与硬件资源限制的前提下，明确各节点的运行次序与资源分配策略，从而实现各计
算单元间的并行运行，并最大限度的降低因缓存容量不足所导致的数据搬运与交换损耗。
问题一的求解关键在于解决峰值内存驻留最小化的排序问题。从目标本质分析，该问
题需要在所有可行的拓扑序列中筛选出一种调度策略，使得并发生存所需要的总缓冲区容
量峰值降至最低，该类问题属于典型的NP-hard 问题。针对卷积、矩阵乘法和注意力机制

等典型算子包含大量节点与边的大规模计算图，直接采用精确的方法获取全局的最优解往
往比较困难。因此，在实际的应用场景中，通常需要借助启发式方法或分解策略来得到可
行的解决方案。

• 专用性模型：该模型以附件中的六个示例计算图为主要测试对象，结合各原子操作已
知的特定信息进行针对性的建模工作。其目标是在给定的条件下尽可能取得全局最优
解，主要用于方法有效性的验证。
• 通用性模型：该模型不依赖于示例中任何特定的计算图结构算子类型，而是通过对机
制的严格分析与推导，设计了具备良好泛化能力的调度策略，适用于结构未知的计算
图任务调度场景，更具说服力。
最终，我们在综合评估两类模型的策略后，将通用性模型作为本问的核心方案。
4.2 专用模型A-基于双层优先级策略的调度算法
在图相关的任务推理与任务调度中，计算图通常表示为DAG 形式，其中节点代表基
础的内存分配、计算和释放等操作，边代表操作间的依赖关系。因此，为了高效管理和使
用内存资源，减少峰值内存使用量，本节提出了一种基于双层优先级策略的贪心调度算法，
该算法通过优先调度内存释放操作和谨慎选择内存分配操作，来优化内存的使用。

设计算图为G = (V, E)，其中：
• V = {v1, v2, . . . , vn} 表示节点集合。
• E = {(u, v) | u, v ∈V } 表示依赖关系边集合。
每个节点vi ∈V 具有以下属性：
• Op(vi) ∈{ALLOC, FREE, COMPUTE}：操作类型。其中ALLOC 表示分配内存
缓冲区，FREE 表示释放内存缓冲区，COMPUTE 表示计算操作。这些操作不直
接影响内存但可能依赖缓冲区数据；
• Size(vi) ≥0：内存需求量。仅对于ALLOC 和FREE 节点有意义，表示申请或
释放的数据缓冲区长度。
• BufId(vi)：缓冲区标识符。用于关联ALLOC 和FREE 节点，以确保每个缓冲
区的分配和释放操作能够正确配对，并避免出现内存泄漏。
本算法主要采用双层贪心策略：以最小化分配内存为原则，第一层策略目标是优先
调度FREE 节点以释放内存，第二层策略是在第一层测率之后已经无FREE 节点时调度
ALLOC 节点，目的是平滑内存使用曲线，降低峰值内存。

4.2.1 约束条件
根据题目的要求，本节我们提出的算法模型必须满足以下约束条件以确保正确性：
·拓扑约束：由于计算图属于DAG 形式，因此必须遵守节点间的依赖关系。在调度
序列中，对于任意边(u, v) ∈E，节点u 必须在节点v 之前执行，以确保数据流依赖：
pos(u) < pos(v),
∀(u, v) ∈E
(4.4)

其中pos(vi) 表示节点vi 在调度序列中的位置索引。
·内存一致性约束：每个缓冲区的ALLOC 操作必须在对应的FREE 操作之前执行，避
免出现内存泄漏或非法访问等情况。对于每个缓冲区b，设ALLOC(b) 和FREE(b) 分别表
示分配和释放缓冲区b 的节点，则有：
pos(ALLOC(b)) < pos(FREE(b)),
∀buffer b
(4.5)
构建计算图时，配对关系通常通过缓冲区标识符进行维护，而上述约束需要在调度过
程中维护节点的入度来完成。
综上所述，拓扑约束是只有当前节点的所有前驱节点都被调度后，该节点才会转为可
调度的状态。内存一致性约束是通过缓冲区的依赖边来隐含确保的，比如FREE 节点通常
依赖于使用该缓冲区的COMPUTE 节点，而COMPUTE 节点依赖于ALLOC 节点。
4.2.2 释放优先策略
当存在可调度的FREE 节点时，算法会从中优先选择释放内存最大的节点，减少当前
的内存使用量，为后续操作提供更多可用的内存空间，一定程度上降低了整体内存的占用
情况。
设Fready 为当前可调度的FREE 节点集合，即入度为0 的FREE 节点：
Fready = {v | Op(v) = FREE ∧InDegree(v) = 0}
(4.6)
其中，InDegree(v) 表示节点v 的当前入度，即未调度的前驱节点数量。
算法选择节点v∗为：
v∗= arg max
v∈Fready Size(v)
(4.7)
这一策略的目的在于尽早释放较大的缓冲区，从而减少内存的过度累积，以此达到优
化内存的目的。
4.2.3 最小分配策略
当没有可以直接调度的FREE 节点时，算法转而选择ALLOC 节点。此时，会优先选
择分配内存最小的节点，让内存使用量缓慢增加，避免内存峰值过早地出现。
形式化地，设Aready 为当前可调度的ALLOC 节点集合：

v∈Aready Size(v)
(4.9)
该策略类似于最短作业优先算法，优先处理内存需求较小的分配操作。

4.2.4 对算法的理论分析
基于上述分析，我们在算法1中展示双层优先级策略算法的伪代码。该算法首先对任

务列表按优先级排序O(N log N)。最后，按排序顺序依次为每个任务分配执行资源O(N)。
综合各步骤，算法相对于节点总数N 的时间复杂度为O(N 2)。

4.5.4 分层协同的全局搜索优化层
本层通过多层次协同机制和全局搜索策略，进一步挖掘调度优化潜力。该层的创新主
要在于将局部重排优化与全局搜索框架进行有机结合，形成了分层协同的优化体系。该层
分为两个主要模块：三阶段局部重排优化和二分搜索全局优化框架，二者协同工作，实现
了从局部到全局的系统性优化。
三阶段局部重排策略：该算法在调度完成后采用系统性的三阶段局部重排策略：
阶段一：拓扑保持的内存友好重排- FREE 节点上提：将FREE 节点尽可能提前到其
所有前驱之后的最早位置- ALLOC 节点下沉：将ALLOC 节点尽可能延后到其所有后继之
前的最晚位置
阶段二：缓冲区使用聚类对于每个缓冲区b，将其使用节点集合Ub 在拓扑约束下尽可
能聚集，减少生存期内的空闲窗口。
阶段三：峰值窗口局部搜索识别产生峰值的调度区间[tp −w, tp + w]，在该窗口内应
用局部搜索，优先提升高解锁收益的操作节点。其中tp 为峰值产生时刻，w 为窗口大小。
二分搜索全局优化框架：为进一步逼近全局最优解，算法采用二分搜索框架。设定下
界L = maxv∈A sv，上界U 为启发式调度结果的峰值，其中A 为所有ALLOC 节点集合，sv
为节点v 分配的缓冲区大小。该框架通过预算约束调度子程序，系统性地逼近最优峰值解，
我们在算法4中展示二分搜索全局优化算法的伪代码。

5 问题二的建模与求解
问题二是问题一的进一步延伸，需要在问题一调度序列的基础上考虑硬件缓存资源的

5.1 基础分析与问题建模
不同于问题一的静态调度优化，问题二考虑带约束的动态内存管理问题，主要的面临
的挑战是在有限的硬件缓存资源约束下，如何通过灵活的设置地址分配策略以及缓存换入
换出机制，来实现计算图的高效执行。根据分析可得，问题二需要遵循以下约束：
• 物理地址约束：每个缓冲区需要分配连续的物理地址空间，且不能与其他缓冲区重叠；
• 容量约束：各级缓存容量有限，同时驻留的缓冲区总大小不能超过硬件容量限制；
• 碎片化约束：地址分配策略需要最小化内存碎片，提高空间利用率和后续分配成功率；
• 换入换出约束：在缓存空间不够用的时候需将数据搬出，造成额外的DDR 访问开销。
面对复杂约束问题时，如何构建底层的硬件仿真平台、充分利用计算节点资源是关键。
本文采用两层结构解决了该类问题：通过底层的硬件仿真框架实现精确的硬件行为仿真；
通过设计多层次协同的自适应内存管理算法形成智能化的缓存资源管理器。

6 问题三的建模与求解
问题三在问题一调度序列和问题二缓存分配方案的基础上，进一步考虑硬件执行的时
间特性，以降低算子的总运行时间为主要目标，同时确保总额外数据搬运量不显著增加。
问题三的核心在于多目标联合优化，需要从工程实际的视角出发，在缓存管理与执行效率
之间找到最佳平衡点。
6.1 基础分析与问题建模
问题三本质上是一个带时间约束的多目标优化问题，其复杂性主要体现在需要同时考
虑两个相互制约的优化目标：
• 主要目标：最小化总执行时间Ttotal，通过优化调度顺序和流水线并行度提升执行效率；
• 约束条件：控制总额外数据搬运量Dspill 不显著增加，保持问题二的缓存管理效果。
与前两个问题相比，问题三面临的新挑战包括：
时间依赖性约束：节点的执行时间不仅取决于其自身特性，还受到硬件单元并行度、
数据依赖关系和缓存访问延迟的影响。
多目标权衡复杂性：执行时间优化往往需要更激进的调度策略，可能增加缓存压力；
而保持较低的数据搬运量则倾向于保守的缓存管理，两者存在本质性冲突。
硬件并行性利用：需要充分利用Davinci 架构中多个执行单元的并行能力，通过智能
的流水线调度实现计算和数据搬运的重叠执行。
为解决上述复杂的多目标优化问题，本文提出了一个两阶段优化策略：在问题二基线
基础上，通过阶段1 关键路径列表调度实现时间最小化，通过阶段2 局部优化与空洞填补
进一步压缩时间，但会增加数据搬运量。根据时间/性能需求可选择方案1 或方案2，从工
程平衡角度推荐使用阶段1。
6.2 两阶段优化策略总体框架
针对问题三的双目标优化需求，本文设计了两阶段优化策略。该策略在问题二缓存管
理基础上，通过两个递进的优化阶段实现时间性能的显著提升。
6.2.1 两阶段优化策略总体设计
两阶段优化策略的核心思想是在问题二基线基础上，通过两个专门化的优化阶段实现
不同程度的时间-搬运量权衡：
优化阶段1：使用基于关键路径列表调度算法对原始节点重新排序，优化执行单元并
行度和流水线效率，实现时间最小化的同时控制数据搬运量增长。
优化阶段2：在阶段1 基础上应用生命周期压缩、SPILL 预取和局部搜索，进一步消
除执行瓶颈，获得更大的时间改进，但在本赛题的用例当中会显著增加数据搬运量。
46
策略选择原则：根据应用场景的时间/性能需求选择合适的优化阶段。对于时间敏感且
可接受较大数据搬运量的场景，选择阶段2；对于需要平衡时间性能与数据搬运效率的工
程应用，推荐选择阶段1。
6.3 优化阶段1：关键路径列表调度算法

算法对不同计算模式的针对性处理能力。
3. 工程平衡优秀
从工程实用角度，阶段1 提供了理想的时间-搬运量平衡。特别是对于Matmul 类算子，
既实现了显著的时间改进，又将数据搬运量增加控制在合理范围内，为工程部署提供了可
行的优化方案。

7.1 模型的优点
在问题的求解中，本文不仅仅考虑了相关算子和附件数据的情况，还重点考虑了实际
情况下的泛化性。在本文的第4-6 章的最后部分，本文均给出了详尽的结果分析，与算法

问题的检查程序，用于检验结果是否符合题目条件约束，检查代码详见附件。
7.2 模型的缺点
核内调度核缓存管理问题属于NP-hard，考虑到对最小缓存驻留、总额外数据搬运量
等参数尽可能的优化，对于超大规模或极端复杂的计算图，算法可能仍然面临计算时间过
长的问题。并且NPU 硬件架构发展迅速，本文所提出的模型核仿真框架均是基于当前版
本的华为Davinci 架构设计，虽然具有一定的通用性，但是当华为Davinci 架构出现更新
时，可能需要做出针对性改进。
7.3 模型的推广
本文的基于华为Davinci 架构建立了相关模型，Davinci 架构具有多级缓存和多种操作
单元，我们的模型严格执行了相关约束，为模型推广提供了可能。例如可以将调度和内存
管理策略推广到循环神经网络（RNN）、图神经网络（GNN）、生成对抗网络（GAN) 等其
他类型的神经网络模型。同时，我们的模型提供了一套自动化的调度和内存管理算法，可
以将这些算法集成到现有的神经网络编译器或硬件设计自动化（EDA）工具链中，完成端
到端的自动化优化解决方案构建。

CACHE_LIMITS = {'L1': 4096, 'UB': 1024, 'L0A': 256, 'L0B': 256,

def check_cache_overflow(allocations):
"""检查缓存容量超限（核心约束）"""
errors = []
for buf_id, (offset, size, cache_type) in allocations.items
():
if offset + size > CACHE_LIMITS.get(cache_type, 0):
errors.append(f"{cache_type}溢出: Buf{buf_id}")

return errors
def check_address_overlap(allocations):
"""检查地址重叠（核心约束）"""
errors = []
sorted_allocs = sorted(allocations.items(), key=lambda x: x
[1][0])
# 按地址排序
for i in range(len(sorted_allocs)-1):
buf1, (off1, size1, _) = sorted_allocs[i]
buf2, (off2, _, _) = sorted_allocs[i+1]
if off1 + size1 > off2:
errors.append(f"重叠: Buf{buf1}与Buf{buf2}")
return errors
def calculate_spill_overhead(spill_ops, buffer_sizes,
has_copy_in):
"""计算SPILL额外搬运量（核心指标）"""
total = 0
for buf_id in spill_ops:
size = buffer_sizes.get(buf_id, 0)
# 有COPY_IN仅算1次搬入，否则算2次（搬出+搬入）
total += size if has_copy_in.get(buf_id, False) else 2 *
size
return total
