## 1. 核心原则

### 1.1 事实优先

论文内容必须有可追溯依据：官方题目、已确认实验结果、对应的已保存数据、已审核分析报告；方法描述还须与实际代码和配置一致。保存过的文件不自动等于正确结果，报告中的“已核验”也不能替代本工作区可复查的核验记录。

禁止编造实验结果、根据趋势猜测数据、使用没有来源的数字或引用。性能、排名、显著性、最优性、复杂度和泛化结论都必须有相应证据，表述不得超过证据范围。

### 1.2 区分事实、解释与计划

区分题目给定条件与新增假设、实测观察与机理推断、已实现方法与计划改进。不确定内容标注“待核验/待补”，不可为补齐篇幅自行补全。影响正确性的缺项先保留占位；其他缺项记入待办，继续不受影响的工作。

## 2. 数据来源规则

论文中的性能指标、加速比、排名和实验结论必须保留来源。内部台账必须有精确来源定位；正文用必要的实验设置、表注、图注、引用或附录解释口径，不机械堆入本地路径。

数据来源查找优先级：

1. [02_confirmed_results.md](02_confirmed_results.md) 中状态为 `CONFIRMED` 的适用记录；这是唯一结果确认台账，不另建 `confirmed_results.md`。
2. 与目标实验版本对应的最新交付报告。
3. a_lab 实验记录。
4. 其他实验报告。

来源优先级只用于查找依据，不代表自动获得入文资格。报告和台账都应追溯到相应版本的数据、配置与核验记录。来源冲突时记录差异并核查原始依据，不能仅按文件更新时间判断正确性。

用于最终论文的数值须满足：来源可定位、实验配置明确、统计口径一致、结果状态为 `CONFIRMED`，且符合本节的历史结果用途约束。

每条结果至少记录：

- 来源文件及精确位置（行、字段、用例键或表格），关联提交号或文件摘要。
- 算法/求解器版本、参数、评估器版本、实例集合、样本量、核数和场景；随机实验还需随机种子。
- 指标定义、单位、基线、聚合方法及失败、缺失、兜底单元的处理。
- 核验人、日期、核验方法、输出记录、适用范围和局限。

被纠正、失效或不再适用于原用途的结果不得作为最终性能结论。经核验且比较条件适当的历史结果可用于基线、消融或方法对照，必须注明版本和用途；不能只因产生时间较早就认定无效。

图表必须关联原始数据、整理数据、生成脚本、版本和指标口径，示意图须明确标注。图表计划记录表达目的；`figs/figure_registry.csv` 记录路径、标签、版本和制作状态，使用同一 ID。**图表/表格 ID 在 05 中分配的同时必须立即登记 figure_registry.csv**（状态可标"计划"），不允许计划与登记表双轨（D029，2026-09-25）。参考文献必须核对真实来源，不得凭记忆补造作者、年份、题名或 DOI。

## 3. 版本管理规则

### 3.1 实验结果状态

| 状态 | 含义 | 使用边界 |
|---|---|---|
| `CONFIRMED` | 已按明确方法和范围核验，记录齐全 | 可在适用范围内作为论文依据；文稿仍需人工审核 |
| `PRELIMINARY` | 已有初步分析，但核验尚未完成 | 仅供讨论或明确标注的工作草稿，不作为定稿依据 |
| `DEPRECATED` | 已纠正、失效或不再适用于原用途 | 不作为当前正文结论依据；保留历史、原因和替代编号 |
| `UNKNOWN` | 尚未确认来源、口径或核验状态 | 不作为论文事实；先定位资料、完成检查 |

AI 或团队成员可以实际开展核验，但必须注明核验者和方法。只有完成与结论范围相符的核验、留下可复查记录，才可标记 `CONFIRMED`；不以用户确认、文件名或报告自述代替数据核验。不要求一律重跑全部模型，但不得夸大已核验范围。

新版本出现不自动使旧版本失效。历史结果仍有效且用于基线时可保留 `CONFIRMED`，明确用途；同一结果只在某个用途失效时写清失效范围，必要时拆成不同用途的记录。

### 3.2 更新联动

结果更新时，通过 [04_claim_evidence.md](04_claim_evidence.md) 检查关联论断、正文数字、摘要、表格、图片和图题。记录新旧结果编号、变更原因和受影响位置；已经审核的受影响文稿重新标为“待人工审核”。

不将 v2 全量、v3 代表样本与波前局部回归混为一组结果。不同版本或样本范围的比较须有明确设计与说明，不拼接成不存在的统一实验。

### 3.3 本地与远端

克隆只需一次。工作开始先检查本地状态，需要同步时拉取团队更新；先妥善保存未提交修改，再合并，不强制重置或覆盖他人成果。阶段性提交与推送按用户当前授权执行；批准本规则不等于授权每轮自动推送。

### 4.3 并行会话规则（D033，2026-09-25）

同一工作区同时开多个 AI 窗口＝多个模型实例**共享同一可写工作树**，即事实上的多 agent 协作，且无锁、无编排、各自内存持有读入时的旧状态。并行会话按以下规则运行：

1. **单写者**：任一时刻一个文件只允许一个会话写入。并行窗口默认承担只读任务（核题面、核代码、文献检索、复算核对）；需要写入的任务由用户指定单一窗口执行。已验证的安全模式：多个只读子代理扇出核料 + 单写者落盘（A013 模式）。核料任务书须自包含，产出要求＝逐字引用＋行号＋出处小节＋末尾"未找到/题面未明说"清单；清单与摘录同等重要，否定性结论（如"题面无某写法"）同样决定正文写法（D037）。
2. **任务声明**：并行写任务开始时在 07 对应任务行登记 `scope`（本任务可写文件清单）、`base`（起始 commit）、`status`；其他会话发现目标文件在他人 scope 内时停手，改为向主窗口提交整合说明。任务收尾交付标准块：`Base commit / Files changed / Evidence used / Assumptions / Needs-integration / Commit`，供整合与追溯。
3. **热点文件收权**：并行期间以下文件只由**主窗口**（整合窗口）维护——全局状态（07、08、11、README）、09 台账，以及多章共用的 **06 术语表、04 论断—证据、05＋figure_registry.csv、references.bib 与 08_references.tex（文献）**；工作窗口不直接改这些文件，把新增术语、论断、图表登记与文献写进交付块 Needs-integration，由主窗口或用户统一落盘。追加编号型条目（D 号、A 号）前先 grep 当前最大编号，避免占号冲突。
4. **镜像按指令同步（D040）**：`sync_to_github.sh` 不自动执行，用户指令推送时统一运行；本地镜像快照提交不受影响。`source_dirty=yes` 的快照含未整合内容，网页 GPT 引用该快照给建议时须注意这一点。
5. **暂不启用 worktree/分支隔离**：当前"人当调度器、每窗口用户在场"的形态下，互链 notes 的跨分支合并无法机械化，整合成本高于收益；若未来出现多个自主写者并发（非人驱动的后台任务），再评估 git worktree + 唯一 Integrator 架构。语义一致性靠交付块声明 + T023 检查脚本兜底，不靠分支隔离。
6. **并行期提交操作**：①add/commit 前必须以 `git -c core.quotepath=false status --short` 全量过目——默认输出把中文路径转义为八进制，grep 过滤会漏看脏文件；②共享台账文件（09 等）已有并行未提交改动时禁止整文件 add：以 `git show HEAD:文件` 为基、单独施加本会话改动，经 `git hash-object -w`＋`git update-index --cacheinfo` 只提交本会话内容，并行改动原样留在工作树；③编号分配（V/A/D/T/F/RES）取工作树版本与台账两者最大值——并行未提交占用在 HEAD 查询不可见；版本号在落稿时实查分配，起草对话不预承诺（D037）。
7. **编译错峰**：`build/` 为共享输出目录，并行窗口不得同时运行 `build.ps1`；落稿编译尽量收拢到主窗口或错峰执行（D039）。

### 4.4 外部评审仲裁流程（D037，2026-09-25）

用户转交的外部评审意见（网页 GPT 等）按以下流程处理：

1. **逐条仲裁**：对照题面原文（13 全文文本版）、决策日志（08）与已定稿正文三方核验后判定采纳/部分采纳/驳回，均附理由。评审方看不到的三样依据——题面原句、D 号、并行会话状态——是其意见的高发错区，也是仲裁引用的重点。
2. **多轮反复**：同一意见经多轮评审反复时，落点须同时化解各轮批评，不是迎合最新一轮。
3. **评分不作为依据**：逐条意见才作数；"可以冻结"类结论不等于用户批准，冻结以用户逐句审定为准。
4. **留痕**：仲裁结果记入对应 A 条目（09）；引发规则级变化的另立 D 号（08）。

写作、排版、评审和交付类任务，另按团队技能 cpmcm-modeling-coach 补读仓库内文件（仓库相对路径）：`skill/references/paper-writing-protocol.md`、`skill/references/paper-quality-gates.md`、`skill/references/typesetting-notes.md`。官方文件要求最高；技能文档与本工作区规则不一致时，以本文件和用户明确指示为准，差异记入决策日志。交稿终检按 [10_delivery_checklist.md](10_delivery_checklist.md) 执行。

生成内容时保留来源信息，标明不确定内容，不补充不存在的信息。AI 在已授权范围内持续整理、起草、修改和检查，无需为常规可逆编辑逐句询问；已经明确的用户选择不重复确认。缺乏依据的最终算法选择或核心结论变更列为待决策项。

`论文.tex` 是唯一正文入口，notes 管理依据与协作状态。上级项目 `sources/` 只读；不为写作改动原始实验输出，自动同步报告、官方评估器和团队模板保留原件。

### 4.5 章节职责、信息唯一载体与预览自查（D047，2026-09-26）

起因：1.4 过瘦（两轮纠偏）与 1.5 过肥（四轮仲裁）方向相反的错误表明，起草缺的是"每节职责基准"，不是校准偏差。本节适用于一切叙述型正文章节；查阅型内容（名词解释、符号表等词条）仍按 D036 词条自足，该豁免不外溢至叙述型节。

1. **职责句先行**：起草或重写任一节前，先写明"本节唯一回答的问题"（范式＝1.5 的"只回答各问解什么、题面要求什么结果"，03 V009 记录）；预览件首行附职责句。
2. **信息主要载体**：完整表述（完整定义、机制细节、数据清单、交付要求等）各指定唯一主要载体——正文、表或图择一承载，公因子只在首处集中表述一次；大纲各节"内容边界"注记指定载体归属（如 1.5 交付说明唯一载体＝TBL-001）。再引用允许但须承担新作用（图表解释、论证性引用、简短回指导航、表/图自足注），禁止换说法复述同一内容——正文逐项抄写表格数据属复述，指出数据支持的结论（如收益在哪个区间趋缓）属新作用；D036 词条自足与第 6 节图表解释均属本条允许的再引用。
3. **延后项注记带深度**：跨节路由的延后项注记须写"目的节＋允许深度"（样例＝01 tex 1.2.3 注记 V009 版："驻留机理留第五章，1.5 至多定义层一句"），不得只写目的节名；旧注记不追溯。
4. **密度对标**：内容必要性与论证完整性优先——篇幅/段数是参照与**双向**异常报警（防冗余、亦防过瘦，1.4 即过瘦先例），不是内容取舍依据；禁止为压篇幅把必要条件压进长句、禁止为凑段数（如三段式）拆并内容。预览件附对标结果——主基准 2025A 国一同节篇幅/段数为标尺，双向偏离均须自证理由；辅基准按 [14_历年A题基准选篇.md](14_历年A题基准选篇.md) 分章匹配仅作范式校验，不作密度标尺，冲突时主基准优先（D041）。图表密度对标先例见 D045。
5. **预览—审定—写入**：整节起草或重写的草稿先在对话中预览全文（含表与图注拟稿），用户确认后写入 tex；预览轮不写 tex、不 build、不占版本号。预览件末附自查＝三问＋两栏＋一扫——三问：有无重复交代（换说法复述）？主次是否分明？每处再引用是否承担新作用？两栏：本节最重要的判断及其证据位置；每处再出现信息的新作用（无新作用则改回指）。一扫：去AI味扫描（skill deai-check，D049）——A 档/B 档超限逐条仲裁（豁免口径见 skill 豁免速查表），预览件末附扫描结论一行。三问＋两栏＋一扫为必答核心，其余节级要点（数字入文四条件、术语对 06、比较句口径、图表 caption 自明等）对照 [18_评审自查清单.md](18_评审自查清单.md) §1（A 档）逐项过一遍，预览件末附"A 档已过、例外与豁免"一行。整章连读门见 [10_delivery_checklist.md](10_delivery_checklist.md) D 节（D048）。
6. **章级落稿自查（B 档门，D050）**：整章写入 tex、编译通过后、章节版本登记（V00N）前，对照 [18_评审自查清单.md](18_评审自查清单.md) §2 执行——B1 连读与一致性（整章连读门为其组成项，D048）、B2 结构与篇幅（三问配比、弃用方法不写大节、目录不预设未冻结组件）、B3 工程门（lint 清零、T023、registry 同步、09 联动）。B 档通过方可登记章节版本；未过项处置后才落版本号。

## 5. 修改规则

修改论文文件前，应明确并简要说明：

1. 修改目标。
2. 修改范围（文件、章节或图表）。
3. 输入资料及使用版本。

这一步是任务范围说明，不是对已授权工作的重复审批。发现关键输入不足时按第1节处理。

修改完成后输出：

1. 修改内容及实际检查情况。
2. 使用资料及其位置/版本。
3. 使用数据来源和结果编号；未使用实验数据时注明“不涉及”。
4. 待人工确认的问题；没有新增问题时注明“无新增问题”，不得虚构审批事项。

只更新本轮受影响的笔记：结果进02，论断进04，图表计划进05，术语进06，进度进07，实质决策进08，AI参与留痕进09。**正文经用户审定落稿（V00N）时，09 中对应 A 条目状态同步推进**（联动规则见 09 第 6 节，D030）。重写或大幅修改正文前，先按 [11_version_log.md](11_version_log.md) 的触发时机留保险快照；用户确认一轮修改后与每日收工时同样留档，版本号与摘要在11登记。修改 LaTeX 后环境可用时编译并查看 PDF；无法编译须记录原因，不宣称排版通过。编译使用 `build.ps1`，其内置 lint（待补标记、未定义引用/交叉引用、Overfull、重复标签）须过目并清零 Overfull 后再提交（D031）。

## 6. 工程记录与论文表达分离

实验日志、调试记录和无关代码细节不直接贴入正文，应转化为与实际实现一致的数学描述、算法流程和实验分析。支撑复现的代码、参数、环境、日志位置保留在工程记录或附录中，不能以“简化表达”为由删去关键条件或改变方法实质。

中文表达准确直接，区分观察与解释；公式解释变量和单位，术语与精度统一。图表先引出再解释其支持的结论，使用稳定标签，不手写编号。图题放在 LaTeX 的 `caption`，图内不重复放图题，按团队要求保存可重绘数据并检查最终尺寸的清晰度。

## 7. 人工审核原则

AI 生成的论文文字、表格、图片及图题必须经过人工审核后才能定稿。审核前可持续推进并保持草稿状态，不必每改一句话就停下等待批准。

文稿审核状态独立于实验结果状态：

- **草稿**：正在准备或仍有待补依据。
- **待人工审核**：已完成本轮自检，可交人工审阅。
- **已审核**：人工审核通过，记录审核人、日期和审核对象的具体版本；仅此状态可标记定稿。

数字、方法、结论或图表发生实质变化时，受影响部分回到“待人工审核”。`CONFIRMED` 结果不自动使引用它的段落成为已审核文稿。

人工重点检查：数字是否正确、结论是否超过证据、方法是否符合实际实现、图表是否支持文字。章节审核记录放在 [03_outline.md](03_outline.md)，具体论断和图表审核可在对应记录中登记。

AI 参与的工作在 [09_ai_usage_log.md](09_ai_usage_log.md) 逐条登记（含人工核验或否决记录），正文与代码按官方附件4落实模型公式、数据分析、编程三场景标注；提交时从该台账整理使用说明。
